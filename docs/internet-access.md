# Доступ к библиотеке из интернета (в т.ч. из России)

Сервер Walle Player работает дома на компьютере (порт **8780**), музыка лежит там же — значит, телефону
снаружи нужен путь до домашнего компьютера. Полученный адрес впишите в окне «Другие устройства» → поле
**«Внешний адрес»**, кнопка «Проверить» покажет, доходит ли запрос. Адрес попадёт в QR-коды слушателей.

Ключи слушателей передаются в каждом запросе, поэтому снаружи нужен **https** (иначе ключ виден по дороге).

## Встроено в Walle Player: «Другие устройства» → «Из интернета»

- **Статический IP — через роутер.** Купите у провайдера статический (белый) IP (у SkyNet ~200 ₽/мес). Программа сама
  найдёт роутер по UPnP, покажет его внешний адрес (и скажет, если он «серый»), откроет порт 8780 и закроет его при
  выходе. Постоянное имя вместо цифр — DDNS-имя в поле «Адрес». UPnP в роутере должен быть включён (у Cudy — включён).
- **Свой сервер (VPS) — туннель.** Любой VPS с Linux и SSH (~100–150 ₽/мес; не «прокси» — к прокси снаружи не
  подключиться). Впишите адрес сервера и пользователя (обычно root), затем один раз на сервере:
  1. «Скопировать ключ для сервера» → добавить строкой в `~/.ssh/authorized_keys`;
  2. «Скопировать команду настройки» → выполнить (разрешает серверу принимать телефоны на порту туннеля);
  3. открыть в брандмауэре сервера порт для телефонов (по умолчанию 8780), например `ufw allow 8780/tcp`.
  Дальше Walle Player сам держит туннель и переподключается. Музыка идёт через сервер — нужен канал от ~5 Мбит/с.
- **Свой адрес** — если доступ настроен иначе (KeenDNS, сервис-туннель): просто впишите адрес.

**https для VPS:** «Скопировать команду https (Caddy)» → выполнить на сервере (root) → вписать имя в «HTTPS-имя». Имя
без регистрации — `<IP через дефисы>.sslip.io` (например `203-0-113-10.sslip.io`), Caddy сам получает и продлевает
сертификат; на сервере должны быть открыты порты 80 и 443. С https туннель открыт только внутри сервера: порт для
телефонов наружу больше не нужен (для пользователя туннеля — `permitlisten="127.0.0.1:8780"`).

## 0. IPv6 от провайдера (бесплатно, без посредника) — если провайдер даёт

При «сером» IPv4 (100.64–100.127, 10.x…) снаружи до компьютера не достучаться, а IPv6-адреса — внешние, без NAT.
Например, SkyNet даёт статическую сеть /56 (включается в личном кабинете, «IPv6 — тест»).

1. Включить IPv6 у провайдера.
2. Роутер: IPv6 включён, WAN — DHCPv6 с **делегированием префикса (PD)**, LAN — SLAAC / RA. Перезапустить WAN.
3. Проверка на компьютере: в окне «Другие устройства» появится адрес «Из интернета (IPv6)» — `http://[2a…]:8780`.
   Walle Player слушает и IPv4, и IPv6 сам.
4. Брандмауэр роутера для IPv6 должен пропускать входящие на порт 8780 к компьютеру (у многих роутеров по умолчанию
   закрыто — правило «IPv6 firewall / разрешить»); брандмауэр Windows — разрешение для Walle Player.
5. Телефону нужен IPv6 в мобильной сети: проверить на телефоне, без Wi-Fi, сайт test-ipv6.com. Если IPv6 у оператора
   нет — снаружи по этому адресу не открыть (тогда нужен посредник, варианты ниже).

Постоянное имя вместо цифр IPv6 — бесплатный DDNS с IPv6 (dynv6.com, DuckDNS): имя → AAAA-запись на адрес компьютера.

## 1. Роутер Keenetic → KeenDNS (бесплатно, проще всего)

Работает и за «серым» IP провайдера (режим «через облако»), даёт https и домен вида `имя.keenetic.pro`.

1. Веб-интерфейс роутера → «Доменное имя» (KeenDNS) → получить имя.
2. «Домашняя сеть» → у компьютера закрепить постоянный IP.
3. KeenDNS → «Доступ к веб-приложениям домашней сети» → добавить: имя `music`, устройство — компьютер,
   порт `8780`, протокол HTTP. Получится `https://music.имя.keenetic.pro`.
4. Этот адрес — во «Внешний адрес».

У других роутеров: «белый» IP + проброс порта + DDNS (TP-Link/ASUS/Mikrotik умеют), но https тогда нужно
настраивать отдельно (обратный прокси, например Caddy) — сложнее.

## 2. Свой недорогой VPS в России (надёжно, от ~150–300 ₽/мес)

VPS (Timeweb Cloud, Selectel, REG.RU и т.п.) с публичным IP становится «входной дверью»: компьютер сам
подключается к нему исходящим соединением (работает за любым NAT), VPS отдаёт https.

- На VPS: `frps` (frp) + Caddy (автоматический https-сертификат на ваш домен или `*.nip.io`).
- На компьютере: `frpc`, пробрасывает `127.0.0.1:8780`.
- Музыка идёт через VPS — нужен канал на нём от ~20 Мбит/с на слушателя (mp3 — 0,3 Мбит/с, с запасом).

Если выберете этот путь — могу настроить: автозапуск frpc вместе с Walle Player и конфиги для VPS.

## 3. Российские туннели (без VPS и роутера)

Сервисы-аналоги ngrok, работающие в РФ (например, tuna.am): ставится клиент, команда вида
`tuna http 8780` выдаёт https-адрес. Обычно бесплатно с ограничениями, постоянный адрес — по подписке.

## 4. Cloudflare quick tunnel (необязательно)

Если положить `cloudflared.exe` в папку данных или `third_party/cloudflared/`, в окне появится кнопка
«Временный адрес Cloudflare». Без регистрации, но адрес меняется при каждом запуске, и в России Cloudflare
работает нестабильно.

## Почему не VPN-сеть (Tailscale, ZeroTier, Radmin)

Работает, но на телефоне занимает слот VPN: Android держит только один VPN одновременно, а он часто уже занят.
Radmin VPN есть только под Windows.
