# Walle Player — API сервера библиотеки (v1)

Сервер раздаёт каталог, обложки и сами аудиофайлы другим устройствам: браузеру (встроенный веб‑плеер на `/`)
и мобильному приложению. Каждое устройство играет само.

**Слушатели.** У каждого человека свой ключ (свой QR), лайки и история прослушиваний привязаны к слушателю,
а не к устройству: один ключ можно открыть на любом числе своих устройств.
- **Владелец** — лайки = «Избранное» на компьютере, прослушивания идут в статистику и «Мою волну» приложения.
- **Гость** — свои лайки и история (таблицы `remote_favorites` / `remote_plays`), владельца не трогают.
- Разметка (настроения, жанры, 👍/👎 догадок «Моей волны») учит модель владельца, поэтому нужна `can_label`
  (у владельца всегда; гостю включается галочкой в окне «Другие устройства»), иначе `403`.

- Запуск: в Walle Player кнопка **«Другие устройства»** (галочка «Открыть библиотеку…») или без окна:
  `python -m musicplayer.server [--port 8780] [--tunnel] [--new-key]` (печатает ссылки всех слушателей).
- Порт по умолчанию **8780**, слушает все интерфейсы. Настройки и слушатели с ключами — `remote.json` в папке
  данных (`%LOCALAPPDATA%\WallePlayer`).
- Интернет: Cloudflare quick tunnel (`cloudflared.exe` в папке данных или `third_party/cloudflared/`) даёт
  временный адрес `https://*.trycloudflare.com`, меняется при каждом запуске.

## Подключение и ключ

QR‑код в окне «Другие устройства» содержит ссылку **`<base>/?k=<key>`**, например
`http://192.168.1.5:8780/?k=AbC…`. Приложение разбирает из неё `base` и `key` и хранит их.

Ключ передаётся одним из способов (по приоритету):

| Способ | Пример |
|---|---|
| заголовок | `Authorization: Bearer <key>` (или `X-Walle-Key: <key>`) |
| cookie | `wp_k=<key>` — ставят `GET /?k=<key>` (303 на `/`) и `POST /api/login` |
| параметр | `?k=<key>` у любого `/api/...` — удобно для аудиоплееров, которым неудобно ставить заголовки |

Ошибки: `401 {"error": "..."}` — нет/неверный ключ; `429` + `Retry-After` (секунды) — адрес заблокирован за подбор: 10 неверных ключей (или неверных секретов запроса доступа, спама запросами) за 10 минут блокируют его на час, повторно — дольше (до недели); IPv6 — подсетью /64. Пока блокировка действует, сервер не отвечает этому адресу ничем, кроме 429. Клиенту стоит показать «слишком много попыток, подождите» и не повторять запросы.
«Сменить ключ» у слушателя сразу отключает все его устройства (остальных не трогает), «Удалить» — тоже.

### Запрос доступа без QR

Устройство без ключа может попросить доступ под именем; хозяин подтверждает в Walle Player на компьютере
(«Пустить как»: нового слушателя или существующего — например, своё второе устройство).

1. `POST /api/join` `{"name": "Петя"}` (без ключа) → `{"id", "secret", "wait": 600}`; `403` с `"code": "home_only"` —
   запросы принимаются только из домашней сети (по умолчанию; показать «подключитесь к Wi-Fi дома или попросите QR»);
   `403` без кода — запросы выключены
   (галочка в «Другие устройства» или сервер без окна), `429` — слишком много запросов.
2. Опрашивать `GET /api/join/{id}?s={secret}` раз в 1–2 с → `{"status": "pending"}`, потом
   `{"status": "approved", "key", "user"}` (ключ выдаётся один раз; браузеру заодно ставится cookie),
   `{"status": "denied"}` или `{"status": "expired"}` (через 10 минут без ответа).

### Обнаружение в локальной сети

UDP на тот же порт (8780): отправьте датаграмму `WALLE_DISCOVER` (широковещательно на `255.255.255.255:8780`
или на адрес), ответ — JSON `{"app": "WallePlayer", "name": "<имя ПК>", "port": 8780, "library": "<id>", "version": "0.3.0"}`.
Адрес сервера — источник ответа. Ключ всё равно нужен (QR или ввод).

**Библиотеку опознавать по `library`** (постоянный id из ответа обнаружения, `/api/ping`, `/api/info`), а не по адресу:
IP компьютера в домашней сети может смениться (роутер раздаёт адреса заново), порт — временно (если 8780 занят).
Если сохранённый адрес не отвечает — найти библиотеку с тем же `library` через `WALLE_DISCOVER` и запомнить новый адрес.

## Объекты

**Track**
```json
{"id": 70, "title": "Ч/Б Кино", "artist": "4 Апреля", "albumartist": "4 Апреля", "album": "Х", "year": 2018,
 "track_no": 4, "duration": 191.9, "genres": ["Rock", "Alternative"], "moods": ["Мрачное"], "mood_conf": {"Мрачное": 0.81}, "feat": [],
 "flags": ["live"], "lang": "ru", "vocal": "voc", "era": null,
 "suggested": [{"mood": "Злое", "conf": 0.72, "source": "model"}],
 "plays": 3, "last_played": 1791013463.8, "added": 1791013463.8, "format": "mp3", "liked": false,
 "cover": "/api/cover/9c43d3b253a6a9aa26ff", "stream": "/api/stream/70"}
```
`cover` может быть `null`. `moods` — настроения трека; `mood_conf` — уверенность модели для тех из них, что модель
поставила сама (остальные поставил человек — показывать без процента); `suggested` — догадки модели (ещё не метки).
`liked`, `plays`, `last_played` — этого слушателя (у гостя — его собственные). Время — Unix‑секунды. Пути относительные: полный URL = `base + path` (+ ключ).

**Волновой трек** = Track + `"wave": {"kind": "known" | "guess" | "auto", "moods": ["Весёлое"], "conf": 0.79}`.
`guess`/`auto` — модель думает, что у трека настроение `moods` с уверенностью `conf`: покажите «Верно? 👍/👎».

## Методы

| Метод | Ответ |
|---|---|
| `GET /api/ping` (без ключа) | `{"app": "WallePlayer", "version", "api": 1, "api_min": 1, "mobile": {...} или null, "name", "authorized": bool, "user": имя или null}` — проверка адреса, ключа и версий |
| `GET /api/app/{file}` | APK мобильного приложения из `mobile` (только самый новый) |
| `GET /api/me` | `{"name", "owner": bool, "can_label": bool}` — кто вошёл |
| `POST /api/me` `{"name"}` | переименовать себя (до 40 символов) → как `GET /api/me` |
| `POST /api/login` `{"key"}` | ставит cookie; `401` если неверный |
| `POST /api/logout` | убирает cookie (веб) |
| `GET /api/info` | `{"name", "version", "api", "tracks", "user": /api/me, "addresses": {"lan": [base…], "internet": [base…]}, "moods": [{"name", "n", "group", "color", "glyph"}], "mood_groups": [...], "characters": [{"key", "name"}], "genres": [{"name", "n"}], "labels": {"genre_tree": [{"name", "color", "subs"}], "eras", "flags": [{"key", "name"}], "langs", "vocals"}, "playlists"}` |
| `GET /api/tracks` | `{"items": [Track], "offset", "more": bool}` — параметры ниже |
| `POST /api/tracks/lookup` `{"ids": [...]}` | `{"items": [Track]}` — свежие данные многих треков сразу (до 2000), неизвестные пропускаются; обновить метки скачанных треков без перекачки аудио |
| `GET /api/tracks/{id}` | Track |
| `GET /api/tracks/{id}/probs` | `{"probs": {"Весёлое": 0.72, ...}}` — вероятность каждого настроения по текущей модели (пусто, если модели или анализа нет); для заливки чипов при разметке |
| `GET /api/artists` | `{"items": [{"name", "n", "liked"}]}` |
| `GET /api/albums` | `{"items": [{"name", "artist", "year", "n", "cover", "liked"}]}` — треки альбома: `/api/tracks?album=…&artist=…&order=album` |
| `GET /api/genres` | `{"items": [{"name", "n"}]}` |
|  | **Жанры** (с 0.4.13) — один словарь (`musicplayer/core/genres.py`): канонические английские имена (с 0.4.33). С 0.4.36 жанры с кириллицей в `/labels` и `/genres` не принимаются: 400 `{"error": "Жанры пишутся по-английски (латиницей): …"}` — клиент показывает этот текст; в фильтре `genre` и поиске русские названия по-прежнему понимаются; склеенные теги (`Post-Hardcore | Pop-Punk`, `Ambient, Psybient`) разбиваются; поджанр всегда приходит вместе с семейством (`["Punk", "Pop Punk"]`), дерево и цвета семейств — `labels.genre_tree`. Клиент показывает имена как есть и не держит своих списков. На запись и в фильтр `genre`/волну можно присылать любое написание (`рок`, `pop-punk`, `рэп`) — сервер приведёт к словарю. С 0.4.26 жанр можно прислать путём `"Семейство/Поджанр"` (`"Punk/Skate Punk"`) (в `genres` для `/labels` и `/genres`): незнакомый поджанр сервер добавит в дерево под это семейство (незнакомое имя без «/» — новым семейством), он появится в `labels.genre_tree` |
| `GET /api/playlists` | `{"items": [{"id", "name", "smart", "n"}]}` |
| `GET /api/playlists/{id}` | `{"id", "name", "smart", "items": [Track], "rev"}` |
| `GET /api/recent?limit=50` | `{"items": [Track]}` — недавно слушал этот слушатель, новые первыми |
| `GET /api/favorites` | `{"tracks": [Track], "albums": [{"artist", "name"}], "artists": ["..."]}` — лайки слушателя (у владельца — «Избранное» компьютера), `rev` — отпечаток списка: не изменился — не перекачивать |
| `POST /api/favorites` | `{"kind": "track", "id": 70, "on": true}` · `{"kind": "album", "artist", "album", "on"}` · `{"kind": "artist", "name", "on"}` → `{"kind", "key", "liked"}` |
| `GET /api/hidden` | `{"items": [{"kind", "key", "title", "sub", "added"}]}` — что этот слушатель скрыл («Не показывать»), новые первыми; экран «Скрытое» |
| `POST /api/hidden` | `{"kind": "track" \| "album" \| "artist" \| "genre" \| "mood", "key", "on": true}` → `{"ok", "kind", "key", "on"}`; `on: false` — «Вернуть». Ключи: трек — id строкой, альбом — `"исполнитель\u001fальбом"` (исполнитель альбома, иначе исполнитель), остальное — имя |
| `GET /api/delete-marks` | `{"items": [{"kind": "track" \| "album", "key"}]}` — что ЭТОТ слушатель пометил на удаление (новые первыми) |
| `POST /api/delete-marks` | `{"kind": "track" \| "album", "key", "on": true}` → `{"ok": true, "kind", "key", "on"}`; `on: false` — снять свою пометку. `400` — неверный kind или пустой key, `404` — такого трека / альбома нет. Ключи как у «Не показывать»: трек — id строкой, альбом — `"исполнитель\u001fальбом"` |
| `GET /api/stream/{id}` | сам файл (`audio/mpeg`, …) с поддержкой `Range` (206) для перемотки; `410` если файла нет на диске |
| `GET /api/cover/{key}[?size=160]` | JPEG, кэшируется надолго (ключ не меняется); `size` — уменьшенная копия (96/160/320/512, ближайшая не меньше) для списков |
| `POST /api/plays` | `{"id", "listened": сек, "at"?: unix, "uid"?: строка}` — засчитать прослушивание (правило как на ПК: >50% трека или 4 минуты); `at` — для отложенной отправки из офлайна ; повтор с тем же `uid` (ответ потерялся — клиент отправил снова) не засчитывается: `{"ok": true, "duplicate": true}` |
| `POST /api/wave/next` | `{"moods": [...], "genres": [...], "character": "mixed", "exclude": [id...], "n": 10}` (жанры сужают волну; только жанры без настроений — все треки этих жанров) → `{"items": [волновой трек]}` |
| `POST /api/wave/rate` | `{"id", "verdict": "like" | "dislike", "kind", "moods"}` (kind и moods — из `wave` трека) → `{"result": "confirmed" | "rejected" | "liked" | "skipped", "moods"}` |
| `POST /api/tracks/{id}/labels` | все метки разом, как лента разметки на ПК; меняются только переданные ключи: `{"moods", "reject", "genres", "flags", "lang", "vocal": "voc"/"inst"/null, "era": 1990/null}` → Track. Словари — `labels` в `/api/info` |
| `POST /api/tracks/{id}/genres` `{"genres": [...]}` | жанры трека целиком (нужен `can_label`) → Track |
| `POST /api/tracks/{id}/moods` | `{"moods": [...], "reject": [...]}` — свои настроения трека (метки), `reject` — догадки, которые не подходят → Track |

Параметры `GET /api/tracks`: `q` (поиск по названию/исполнителю/альбому/жанру/настроению, префиксы, кириллица),
`mood`, `mood_status` (`confirmed` по умолчанию | `suggested` | `any`), `genre`, `artist` (исполнитель, исполнитель
альбома или участник feat), `album`, `year`, `not_played_days`, `order` (`artist` | `title` | `album` | `year` |
`play_count` | `last_played` | `added` | `duration` | `random` | `rare_random` — случайно с уклоном в редко
слушанное), `desc=1`, `limit` (≤ 500, по умолчанию 100), `offset`, `hidden=1` — показать и скрытое.

### «Пометить на удаление» (с 0.4.42)

Просьба владельцу удалить трек или альбом (плохая запись, дубль). **Помечать может любой слушатель** (и гость без
`can_label`): это только просьба — сервер ничего не удаляет. Владелец видит общий список в программе на ПК («На удаление»
в боковой панели: кто и когда пометил) и сам решает: «Удалить…» (файлы в корзину Windows) или «Снять пометку». После
удаления трек пропадает из `/api/tracks`, а пометка — из `/api/delete-marks`; снятая владельцем пометка тоже исчезает у
слушателя. Гость видит только свои пометки. Клиенту: пункты «Пометить трек на удаление» / «Пометить альбом на
удаление» в меню трека (если уже помечено — «Снять пометку удаления»), после пометки — «Отменить» (`on: false`).

### «Не показывать» (с 0.4.24)

У каждого слушателя своё (по его ключу; владелец — то же, что на компьютере): трек, альбом, исполнитель, жанр,
метка (настроение). Скрытое не играет в `/api/wave/next` и не приходит в `/api/tracks` (и поиске), `/api/artists`,
`/api/albums`, `/api/genres`. Плейлисты, «Любимые» и `/api/tracks/lookup` отдают всё как есть. Клиенту: пункты «Не
показывать трек / альбом / исполнителя» в меню трека, жанр и метку — долгим нажатием на чип волны; сразу после —
«Отменить» (`on: false`); список с «Вернуть» — `GET /api/hidden`. Жанры и метки волны клиент фильтрует сам по этому
списку (`/api/info` отдаёт словарь целиком — он нужен для разметки).

### «Моя волна» на клиенте

1. `POST /api/wave/next` с выбранными настроениями и характером (`favorite` | `unfamiliar` | `mixed` | `weak`).
2. Играть по очереди; когда до конца осталось 2–3 трека — снова `wave/next` с `exclude` = id уже полученных.
3. Только если выбраны настроения: у трека с `wave.kind` `guess`/`auto` показывать «Модель думает: «…» (79%). Верно?»: 👍 → `wave/rate like`,
   👎 → `wave/rate dislike` и следующий трек, «Другое…» → `POST /api/tracks/{id}/moods`.
4. Засчитанное прослушивание → `POST /api/plays`.

### Состояние связи

Аудио отдаётся как файл с `Range` — плеер начинает играть сразу и докачивает по ходу. Клиент должен показывать
буферизацию (долго нет данных — «медленная связь»), отличать обрыв связи от битого трека (`GET /api/ping`
недоступен → «нет связи», ждать и продолжить с той же позиции; ping отвечает → трек пропустить) и после
восстановления перезагрузить то, что не догрузилось.

### Музыка на устройстве (офлайн)

Скачивание — забота клиента, отдельного API нет: полный `GET /api/stream/{id}` (без `Range`) и `GET /api/cover/{key}`,
метаданные трека сохраняются вместе с файлом и обновляются отдельно через `POST /api/tracks/lookup` (веб-плеер —
при подключении не чаще раза в 10 минут и при открытии «Скачанного»), аудио не перекачивается. Без связи клиент играет скачанное (в «Моей волне» — случайные скачанные
треки), а засчитанные прослушивания копит и отправляет потом в `POST /api/plays` с полем `at`.
Веб-плеер хранит файлы в IndexedDB (работает и по http в домашней сети); открыть сам плеер без связи можно только
по https/localhost — тогда его страницы и обложки держит service worker `/sw.js`.

### Версии и обновления

- `version` — версия Walle Player на компьютере (история — `CHANGELOG.md`). Веб-плеер сравнивает её с той, с которой
  загрузился, и предлагает «Обновить» (раз в 10 минут, при возврате во вкладку и при восстановлении связи).
- `api` — версия API сервера, `api_min` — самая старая, которую он ещё понимает. Клиент знает свою версию API:
  если она больше `api` — «Обновите Walle Player на компьютере»; если меньше `api_min` — «Обновите приложение».
  Добавление полей и методов версию не меняет — клиент должен игнорировать незнакомые поля.
- `mobile` — `{"version", "file", "url", "size"}`: самый новый APK, который владелец положил в
  `%LOCALAPPDATA%\WallePlayer\mobile` с именем `WallePlayer-1.2.0.apk`. Если версия новее установленной — показать
  «Есть новая версия приложения» и скачать `GET url` (с ключом).
- Клиенту стоит слать заголовок `User-Agent` с `WallePlayerApp/<версия>` — так он виден в списке устройств на компьютере.

### Адреса библиотеки (дома и из интернета)

`/api/info` → `addresses`: все базовые адреса этой библиотеки — домашние (`lan`) и внешние (`internet`: статический IP
через роутер, свой VPS-туннель, свой адрес, IPv6). Клиент, подключённый дома по домашнему QR, сохраняет внешние адреса в
профиль библиотеки и вне дома пробует их сам (ключ тот же). Список меняется, когда владелец меняет способ доступа —
обновлять его при каждом подключении.

Сервер блокирует адрес за подбор ключа: ответ `429` с `Retry-After` (секунды) на любой запрос. Клиенту — показать
«слишком много попыток, подождите N минут» и не повторять запросы до этого времени.
